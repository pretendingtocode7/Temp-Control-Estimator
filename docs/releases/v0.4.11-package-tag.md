# v0.4.11 Package-tag catalog correction

The catalog previously admitted active Books items with `cf_for_estimate` checked.
That excluded the supplied, correctly tagged composite and included older untagged
items. Eligibility now requires an active Books item assigned the **Package**
reporting tag's **Package** option. The old checkbox no longer grants or prevents
eligibility. Item names, descriptions, custom category text, Package Tier and the
composite flag do not substitute for the actual assigned tag/option IDs.

The catalog resolves the unique active `Package` tag from Books `/reportingtags`
and its unique `Package` option from `/reportingtags/{tag_id}/options/all`. It
then compares both IDs on every admitted item. This avoids embedding one
organization's IDs in source. Missing, ambiguous, inactive or malformed metadata
fails closed; it never falls back to the old checkbox catalog. Books `/items`
already includes the required composites, so no Inventory access or new
credentials are needed. Components are not expanded or rewritten.

Search filters the complete paginated active Books list before applying existing
type, brand, text and result limits. Only a complete, validated list is cached.
The new cache namespace includes policy, organization, tag and option; cached
entries carry matching eligibility proof. The list cache is capped at 15 minutes
instead of the old 12-hour catalog constant. `get_item()` bypasses the old
normalized item cache and reads item tags/status afresh. Preview and generation
already hydrate selected IDs through that method, so a stale selection cannot
authorize a new estimate after its tag/status is removed. Successful idempotent
replays and existing estimates/queued sends are not retroactively changed.

The source override is
`app/reconstruction/runtime/includes/class-equipment-catalog.php`. A settings
override changes only the two catalog-test messages, and the picker empty-state
guidance now names the Package tag. The release recipe explicitly stages the
catalog, settings and existing enqueue overrides, rebuilt assets and version
metadata into a separate 47-file package. The original installer and all 45
runtime reference files remain unchanged. The worker cache version becomes
`0.4.11`, invoking its existing cleanup of older estimator caches without
touching unrelated applications' caches.

Validation before release:

- Read-only live inspection confirmed the prior v0.4.10 installation still
  matched all 47 package files. The supplied composite is active, has the actual
  Package tag/option and lacks the old checkbox. The standard Books item list
  exposes its assigned tags.
- A complete read-only audit found 220 active Package-tagged items and 132
  active checkbox-enabled items without that tag. No Books records were changed.
- The isolated catalog harness passes 39 cases and 199 assertions using only
  synthetic responses and an in-memory cache. It covers exact ID membership,
  checkbox independence, malformed/wrong tags, status, provider errors,
  pagination, missing/mismatched item IDs, cache migration/proof and organization
  isolation, plus rejection after a previously selected item's tag is removed.
- The frontend suite passes 124 tests, including the corrected empty guidance.
  Full packaged PHP, browser cache-migration and live release verification are
  recorded separately by the release operator.

Private catalog samples and rollback backups are excluded from GitHub. Live
verification must remain read-only: no customer emails, Books transactions or
approval actions. An older item that still has the valid Package tag and remains
active is intentionally eligible; this release does not guess age-based
retirement or modify Books data.

API references: [Books items](https://www.zoho.com/books/api/v3/items/) and
[reporting tags](https://www.zoho.com/books/api/v3/reporting-tags/). The observed
list envelopes are `tags` and option `results`, which the tests reproduce.
