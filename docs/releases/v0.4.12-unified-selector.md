# v0.4.12 unified equipment selector

One picker now supplies Package, AC, Furnace and Coil choices for each system.
BTU, tonnage and text filters combine on the server before pagination. Users can
browse beyond the first 100 catalog records. Filter/category changes immediately
clear old results, delay requests briefly to coalesce typing, and reject stale
responses or stale selection handlers.

The existing active **Package reporting tag → Package option** rule still applies
to all four categories. Verified Books data contains 140 composite packages,
19 individual AC units, 44 furnaces and 17 coils. Composite truth comes from
`is_combo_product`; recognized structured equipment types take precedence for
individuals, with explicit bounded item-name descriptors as a fallback. The
custom category text `Package` cannot distinguish the components and is not used
to turn them into composites. Unknown or ambiguous types are excluded from the
four-category selector.

Ratings use positive, complete structured values first, supporting commas and
explicit units. `custom_field_hash`, inline fields and custom-field arrays are
recognized. A present invalid or conflicting structured value stays unknown.
When structured ratings are missing, only an explicit number adjoining a BTU or
ton unit in the parent item name is accepted. Model digits, AFUE/SEER figures and
component capacities are never substituted. BTU means input BTU; output BTU is
kept separate. The supplied package is 1.5 tons / 100,000 BTU even though its coil
is rated 2 tons. Items without a rating remain available with that filter set to
All. Category-wide facets are numerically sorted.

`GET /equipment?selector=1` returns an envelope containing `items`, `total`,
`page`, `per_page`, `has_more` and `facets` (`btus`, `tons`). It accepts category,
query, BTU, tonnage, page and bounded limit arguments. The existing array response
for requests without `selector=1` remains available. Unknown item types are no
longer relabeled as whichever type was requested. Catalog policy cache version
and the v0.4.12 worker version prevent reuse of older unclassified results.

Selecting a package stores `equipment.package` and removes only this system's
AC/furnace/coil selections. Picking an individual component removes the package
and preserves the other components. Existing accessory selections, descriptions,
notes and permit pricing survive; they are not offered as extra Add tools in the
new four-category picker. A package is one actual Books item and one priced line,
quantity one. Its component contents are not separately charged.

Both Preview and Generate validate freshly hydrated identities and canonical
slots before rendering, audit creation or provider writes. Package/component
conflicts, hidden aliases, category/slot mismatches, duplicate items within one
system and duplicate/invalid system numbers fail closed. The same item may be
used in distinct numbered systems. Successful idempotency replays retain their
original behavior.

Renderer and Books edit/payload ordering explicitly recognize Package. Legacy
saved templates without a working package/items section receive an escaped
compatibility section, including the actual name and amount; stored posts are
not rewritten. Generic and explicit package layouts avoid duplicate sections.
The annexure also retains the package name instead of reducing it to a model.
No live customer email, estimate, CRM transaction or approval is needed for tests.

## Validation

- Full frontend unit/component/API/worker tests and the production build.
- Standalone catalog cases cover exact tag identity, normalization, ambiguous
  capacities, combined filters, pagination, cache proof and selection boundaries.
- Standalone endpoint/rendering/generation tests use the real catalog validator
  with in-memory providers; they verify one priced package line, rejection before
  writes, stable edit keys, legacy template visibility and successful replays.
- An isolated audit of the complete private Books snapshot verifies all four
  category totals, all 140 packages across pages and the supplied parent/component
  capacity examples. Private item IDs, descriptions and prices are not published.
- `npm run test:selector` runs desktop/mobile shared-picker, filtering,
  pagination, race protection, replacement math, multisystem, review, draft and
  synthetic PDF flows with all external services mocked.

The original installer and all 45 runtime reference files remain unchanged.
Release packaging overlays eight explicitly listed PHP overrides and rebuilt
assets into the separate installable. Live release/version, backup, HTTP and
read-only integration results are recorded by the release operator. Real
provider writes, existing users' live browser migration and physical Safari/iOS
remain outside offline verification. CRM settings metadata was not accessible
with the existing token; actual acceptance of the Package slot there is not
claimed. No credentials or provider settings are changed.
