# v0.4.13 efficiency, proposal and pricing corrections

The shared Package / AC / Furnace / Coil picker adds an **Efficiency (%)**
filter. It combines with category, text, input BTU and tonnage before pagination.
Category-wide efficiency facets use valid AFUE percentages. Explicit structured
AFUE values take precedence; a missing structured value may use an explicit
parent-name percentage adjoining AFUE. Invalid or conflicting structured values
remain unknown. SEER, model digits and unrelated percentages never become AFUE.
Current tagged package/furnace names supply 80%, 96% and 97%; AC/coil items without
a percentage remain available under All. The exact Package reporting-tag rule
and package/component mutual exclusion are unchanged.

## Cost and sales

**Equipment subtotal (cost)** in the tool shows actual purchase cost.
**Project total** starts from selected equipment sales prices and remains editable.
Once the technician edits the sales total, later equipment, note or rebate changes
do not replace that manual total. Use equipment sales price explicitly resumes
the equipment-sales calculation. Equipment cost has its own independent override.

Individual item cost uses the actual Books `purchase_rate`. Composite parents in
the current catalog report zero purchase rate, while their detail responses
include `mapped_items` with component purchase rates and `mapped_quantity`.
The selected package's fresh detail supplies a complete, bounded, validated
sum of component cost times quantity. No component sales rate or markup is used,
and the package's sales rate is still priced once. A positive explicit parent
purchase rate is authoritative; an unestablished zero parent cost or incomplete,
invalid or nested mapping remains unknown. List browsing does not fetch details
for every package. Selection loads one item's details with visible pending/error
states and rejects late, mismatched or stale selections.

Missing cost is blank with a visible explanation, never a sales-price fallback
or a partial total disguised as a complete cost. Actual known zero cost remains
zero. Internal cost and override flags are excluded from the request payload.
The existing wire `pricing.subtotal` retains sales-subtotal semantics for Books
compatibility; it is not the cost field displayed by the tool.

## Customer PDF

The client-generated proposal PDF places the package under **Equipment to Be
Installed**. The two inspected live templates share a verified legacy token
layout, so a render-only template copy gains an explicit package row within that
equipment list. Stored template posts are not edited. A generic or explicit
package template retains its existing placement. A compatibility fallback remains
for other unsupported layouts rather than silently hiding selected equipment.

All structured equipment line financial fields are removed from the customer
document view. The customer summary retains project sales total and deposit;
the verified legacy subtotal row is omitted. Package and permit compatibility
sections have no line price. Internal catalog data and Books line sales rates
stay available to the transaction builder and authenticated Books editor.
This changes the app's proposal/PDF, not the separate native Books PDF template.
Manually authored free-text prices are not automatically removed from descriptions.

PDF pagination keeps the same Letter page geometry and single canvas capture,
but chooses nearby blank row bands before cutting a page. This prevents the
observed footer text clipping without discarding or duplicating captured pixels.
The inspected legacy condenser specification token is also balanced when only
tonnage or SEER is known; authored template posts remain unchanged.

## Verification and provenance

Synthetic catalog, component, endpoint, rendering and browser tests cover combined
efficiency/capacity filters, malformed values, missing cost, mapped quantities,
cost/sales separation, manual total preservation, stale selection requests,
one-priced-package Books payloads and legacy PDF placement without line prices.
Real provider data is inspected read-only and retained privately; committed
fixtures contain synthetic identities and amounts. Browser checks use the actual
PHP-rendered synthetic proposal from the inspected template layout.

The exact saved v0.4.8 installer and all 45 original runtime reference files stay
unchanged. Editable reconstruction and explicit PHP overrides remain separate;
release packaging projects them into a versioned installable with matching
JS/source-map output and a fresh worker cache version. Release-operator evidence
records the exact commit/package, test counts, backup, deployment and live checks.
No real customer email, estimate, Books/CRM write or approval is required to verify
these changes. Existing physical Safari/iOS sessions and real provider writes
remain outside the automated checks.
