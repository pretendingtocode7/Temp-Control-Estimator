repairs and frontend source-search results are documented in
[v0.4.8-maintenance.md](v0.4.8-maintenance.md); the saved runtime files and ZIP

## Limitations recorded at import

The historical standalone smoke test does **not** pass unchanged. It stops
when the renderer calls the WordPress translation function `__()`, before the
test defines its shim. With only that translation shim supplied externally,
33 assertions pass and one case-sensitive `10-Year` warranty-text assertion
fails; the saved version uses the newer proposal-note wording. The test then
stops at its call to the removed `build_deluge_payload()` method. v0.4.8 uses
`build_transaction_payload()` and direct Books/CRM calls instead. The legacy
generator PHPUnit test also targets the removed method. These tests are
preserved for follow-up work rather than changed to make the import pass.

The installer contains built frontend assets, but no v0.4.8 React source,
package/lock files, or Vite configuration. It cannot reproduce the frontend
build. The readme's npm-build instructions and retained historical development
files should not be taken as a complete v0.4.8 development checkout.

Full PHPUnit/WordPress integration, Zoho transactions, WP-Cron, PDF/email
delivery, and production behavior were not exercised. No plugin was installed
or deployed, and no website was modified.
