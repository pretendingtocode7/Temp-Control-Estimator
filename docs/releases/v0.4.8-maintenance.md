## Test maintenance

- Load test-only WordPress translation/escaping/identity/time stand-ins before
  renderer execution. Offline tests use the actual bundled Mustache fallback,
  rather than a copy of its implementation inside the smoke test.
- Assert the selected v0.4.8 parts/labor warranty notes, including unselected
  notes, edited descriptions, permit price bounds and escaped legacy-template
  compatibility sections.
- Test `build_transaction_payload()` and Books preview edit keys, separate
  Books/CRM IDs, project-price adjustments, multi-system/permit rows, Unicode
  deal names, selected proposal terms, and text edits that cannot change item
  IDs, quantities or catalog prices. Proposal HTML is tested separately from
  the plain Books approval notes.
- Exercise draft creation with an in-memory Zoho double: `send=false`, minimal
  provider line payloads, propagated transport/validation errors, missing IDs,
  and rejected non-draft responses with synthetic cleanup. No HTTP/email
  implementation is loaded for these smoke checks.
- Use PHPUnit-discoverable `*Test.php` names, include the generator in the unit
  suite and replace the obsolete PHPUnit XML attribute. Only encryption tests
  skip for missing libsodium; HMAC/ID/equality tests still execute.

- PHPUnit: **40 tests discovered, 33 executed successfully, 160 assertions,

  with the saved import after maintenance; no runtime file changed.

For a normal PHP development environment:

```sh
php tests/smoke.php
composer install
vendor/bin/phpunit -c tests/phpunit.xml
```

Composer's real Mustache implementation takes precedence when installed;
otherwise standalone PHPUnit uses the same bundled fallback as the installer.
Set `WP_TESTS_DIR` to a disposable WordPress test environment for the four
integration tests, and use PHP with libsodium for the three encryption tests.
The isolated run did not exercise live WordPress, real Zoho transactions,
WP-Cron, PDF/email delivery, credentials or deployment.
